# 数据生命周期只读脚本

本目录是 M2 的审计与 dry-run 输入，不是生产删除工具。所有脚本默认只做 `SELECT`，不包含 `UPDATE`、`DELETE`、`DROP`、`ALTER` 或建表。

执行原则：

1. 只能由只读数据库账号执行；会话先设置 `SET SESSION TRANSACTION READ ONLY`；
2. 依次执行 `00`，再按目标执行 `01`—`06`；
3. 保存时间、环境、数据库版本、脚本 SHA-256 和聚合输出；
4. 输出不得复制邮箱、剧情正文、密钥、错误详情或玩家 ID 到仓库；
5. 候选数变化属于正常现象，生产动作不能使用文档中保存的旧数量；
6. 任一表或字段缺失、数量异常、跨账号父子命卷或在途点数预占都视为阻塞；
7. 真正写入脚本只在安全删除服务和隔离副本恢复演练完成后另行生成，并需要单独生产授权。

完整决策、删除顺序和回滚边界见 `docs/data-lifecycle-plan.md`。

`06-log-attribution-preflight.sql` 把模型日志分为现存命卷可归属、创建命卷前和孤立旧命卷三类，并只以计数检查错误字段、
管理操作与运行错误中的可识别文本。受控写入脚本另放在 `database/maintenance/account-lifecycle`，不属于本目录的只读基线。

# V0.15 可信剧情管线设计

> 状态：当前实施方案
>
> 最近更新：2026-08-15
> 适用范围：V0.15 轻叙事引擎、H5 回合推进、真实模型灰度回放

## 1. 目标与边界

V0.15 只解决一件核心问题：让自由叙事形成可信、可持续的命卷。

产品承诺保持不变：

> 已确认的经历不可被遗忘，已落定的事实不可被悄悄改写；玩家可以自由尝试任何尚未发生的可能，但结果只有在剧情完成并提交后才会成为新的事实。

本阶段不建设精密战力、统一物价、固定职业树或强制世界主线。Java 也不通过姓名词表、关键词或正则决定开放世界行动是否成功。

## 2. 当前灰度问题的共同根因

真实灰度样本已经证明，数据库事务和失败不落库是有效的，但模型生成的语义没有先被编译成稳定引用：

- 同一人物改名后被创建成两个角色；
- 模型抄错既有实体名称、类型或稳定 ID，导致整个回合失败；
- 从物品中学到的能力没有形成能力实体，后续被判定为“尚未掌握”；
- 模型把人物错误附加物品保管关系，或把能力绑定到来源物品的 ID；
- 玩家明确授权“数月后”“闭关三年”，仍被当成篡改当前时间；
- 所选世界模板被当成不可修订的宇宙真相；
- 内部结构错误、玩家事实冲突和 AI 越权使用同一种失败反馈。

因此不能继续增加单个名字或剧情专用补丁。需要把“理解语义”和“保存事实”之间补成一条正式协议。

## 3. 权威职责

| 参与方 | 负责 | 不负责 |
|---|---|---|
| 玩家 | 提出行动、授权时间跨度、决定重大选择、显式修正事实 | 直接宣布行动一定成功、静默覆盖已确认历史 |
| 行动理解模型 | 判断行动语义、对象含义、授权边界、事实冲突候选 | 猜数据库 ID、直接写数据库 |
| 剧情模型 | 演绎过程、局部结果、生成下一步局势 | 替玩家作出未授权重大决定 |
| 事实投影模型 | 从已完成剧情提取需要长期保存的变化 | 决定数据库主键、事务顺序和最终合法性 |
| 独立审阅模型 | 检查事实矛盾、玩家决定越权和遗漏变化 | 作为唯一事实来源 |
| Java 服务 | 编译引用、分配 ID、校验生命周期/数量/归属/时间、原子提交、幂等恢复 | 使用业务关键词猜剧情胜负 |
| 数据库 | 保存已提交事实、别名、事件、回合和审计历史 | 把叙事正文自动视为全部事实 |

## 4. 目标回合流程

```text
玩家行动
  → 行动理解
  → 实体引用编译
  → 剧情生成
  → 可信事实投影
  → 独立审阅
  → Java 归并与原子提交
  → H5 返回剧情、事实变化和下一步行动
```

正常回合当前使用五次职责单一的模型调用：

1. Flash 行动理解；
2. 当前平台模型生成剧情；
3. Flash 提取可信事实变化；
4. Flash 审阅事实一致性；
5. Flash 审阅玩家决定边界。

修复调用只针对失败阶段，不因正文略短而重写整章。内部结构修复不得伪装成玩家输入错误。
两个审阅阶段暂不为了追求速度强行合并；只有真实回放证明合并后仍能稳定识别事实冲突和玩家决定越权，才允许减少调用。

## 5. 实体引用协议

### 5.1 模型只使用回合引用键

行动中提到的人物、物品、能力和地点先得到本轮 `referenceKey`。模型不再反复复制数据库的稳定 ID、实体类型和标准名称。

服务器根据当前投影、历史别名和来源证据把引用编译为：

- `EXISTING`：已经有稳定实体；
- `ESTABLISHED`：已在可信来源出现，但尚未晋升长期实体；
- `NEW`：本轮允许新建；
- `UNRESOLVED`：不能证明为既有事实，但仍可能作为查询或尝试对象。

稳定 ID、实体类型和标准名称以服务器投影为准。模型抄写差异不能直接让整轮失败。

### 5.2 永久别名与显式改名

人物、灵宠、物品和能力允许拥有多个历史别名。改名不是创建新实体：

- 原稳定 ID 不变；
- 新名称成为当前展示名；
- 旧名称进入永久别名表；
- 后续使用任一别名都解析到同一实体；
- 只有玩家明确改名或已完成剧情明确形成新称呼时才写入别名。

不把正文中所有称谓自动永久化，也不依赖模糊词匹配合并实体。

### 5.3 最小表结构

新增 `story_entity_alias`：

| 字段 | 说明 |
|---|---|
| `id` | 别名记录 ID |
| `save_id` | 命卷 ID |
| `entity_id` | 对应稳定实体 ID |
| `alias_name` | 原始别名 |
| `normalized_alias` | 只用于同命卷精确归一查找的标准形式 |
| `alias_type` | 原名、改名、称号、来源称谓 |
| `source_turn` | 首次确认该别名的回合 |
| `active` | 是否仍可用于解析 |
| `created_at` / `updated_at` | 审计时间 |

不在本阶段新增向量库、通用知识图谱、战力表或世界模拟表。

## 6. 能力可信状态

能力使用显式生命周期：

```text
KNOWN → LEARNING → MASTERED
                    ↓
          TEMPORARILY_BLOCKED
                    ↓
                  LOST
```

- `KNOWN`：已经知道能力或功法存在；
- `LEARNING`：正在学习，尚不能等同完全掌握；
- `MASTERED`：已经掌握，可作为后续行动前提；
- `TEMPORARILY_BLOCKED`：仍掌握但当前无法施展；
- `LOST`：已经失去；
- `UNKNOWN`：只用于无法还原的旧数据，不作为新回合正常状态。

能力可以记录来源物品、传授人物或事件引用，但来源物品和能力必须是不同实体。阅读玉简学会功法时，玉简仍是 `ITEM`，功法创建或更新为 `ABILITY`。

## 7. 时间、世界和事实语义

行动理解必须明确区分：

- `DO_NOW`：当前时段内行动；
- `ADVANCE_FUTURE`：玩家授权推进到未来；
- `ASSERT_PAST`：玩家声称过去已经发生；
- `REVISE_WORLD`：玩家主动调整当前世界设定；
- `CORRECT_FACT`：修正已经落定的命卷事实。

例：“闭关三年突破元婴”包含两个不同部分：

- 闭关三年是玩家授权的时间跨度；
- 突破元婴是玩家希望尝试的结果，剧情可以成功、失败或产生代价，不能预先当成既成事实，也不能仅因当前境界低就拒绝整条输入。

世界采用“软起点 + 动态强事实”：世界模板可以被玩家扩展或显式修订；已经在该命卷中发生的经历不能被模板或新剧情静默抹除。

## 8. 失败分类与恢复

### 8.1 玩家事实冲突

只有输入确实依赖一个与权威事实矛盾的过去前提时才拒绝，并返回：冲突事实、当前记录、可行改写方式。

### 8.2 内部协议错误

缺少 ID、抄错类型、遗漏归属、引用键错误等属于系统内部错误：

- 自动在对应阶段重新编译或精简修复；
- 不消耗正式回合；
- 不向玩家提示“换一种行动”；
- 超过恢复上限时返回可追踪的问题编号和“本轮未提交”。

### 8.3 玩家决定越权

事实提案合法但正文替玩家作出新的重大决定时，只重新生成正文，不重复行动理解和事实检索。

### 8.4 请求进行中与重复提交

同一请求重复点击应复用请求 ID 并查询原任务结果。H5 显示仍在推演或已完成，不创建第二个回合。

## 9. 分阶段实施

### 第一阶段：建立可测协议

- 固化本文与真实回放用例；
- 补充实体引用编译器；
- 既有稳定实体由服务器回填类型和标准名称；
- 清除非物品上的无意义保管字段；
- 明确内部结构错误与玩家冲突的不同响应。

### 第二阶段：身份与能力连续性

- 增加永久别名表和显式改名写入；
- 增加 `KNOWN`、`LEARNING` 能力状态；
- 保存能力来源引用；
- 验证同一人物/灵宠改名前后不重复创建。

### 第三阶段：时间与软世界

- 行动契约携带语义范围、明确时长和预计结束时刻；
- 长时行动按量级推进；
- 创角设定先形成当前世界事实，再进入第一回合；
- 世界模板与命卷已确认事实分层。

### 第四阶段：拆分剧情与事实投影

- 剧情模型不再同时承担完整数据库补丁；
- Flash 从完成后的剧情提取事实提案；
- 独立审阅合并检查事实与玩家决定；
- 分阶段修复，减少整章重生成。

## 10. 验收用例

发布前至少完成以下真实模型、真实 RDS 回放：

1. 小冰霜狼改名为霜刃后仍是同一实体；
2. 从上古玉简学会苍龙引气诀，物品和能力不会共用 ID；
3. 学习血煞诀后下一轮可以继续修炼；
4. 寒霜掌从知晓、学习到掌握的状态连续；
5. 闭关三年会推进相应时间量级；
6. “三年后突破元婴”被识别为时间授权加目标尝试；
7. 玩家错误声称某人过去已经死亡时得到事实冲突说明；
8. 玩家观察当前濒死人物并猜测其会死亡时不被当作过去事实拒绝；
9. 现代、末法或无神创角设定能形成该命卷的软世界起点；
10. 新增子地点不会覆盖已有地点历史；
11. 把物品交给本轮新人物时，人物只创建一次且保管者正确；
12. 消耗物品后数量和归属同步；
13. 已死亡人物在没有明确复活事件时保持死亡；
14. 剧情在下一项重大决定前停止。

量化门槛：

- 机械结构导致的回合失败低于 2%；
- 已确认事实无静默回滚；
- 不出现未授权重大决定；
- 正常请求不出现超过 90 秒无结果且无法恢复；
- 失败请求不增加回合、revision 或改变实体状态。

## 11. 发布原则

- 所有变更先在 V0.15 隔离服务和授权 RDS 测试命卷验证；
- 表迁移必须可重复执行并在部署前单独验证；
- 不批量重写 V0.14 历史正文；
- 旧能力 `UNKNOWN`、旧名称和旧实体通过兼容读取逐步补全；
- 一批改动只有通过单元测试、真实模型回放和手机 H5 冒烟后才提交发布。

## 12. 2026-08-15 实现与隔离验证结果

- 已实现稳定实体引用编译与永久别名持久化，不以人物名称词表或模糊匹配决定身份；
- 已实现显式改名、能力生命周期、事实投影、长时间授权归一和协议错误恢复；
- 事实投影只能提交结构化变化，不能改写已经生成的正文、标题和选项；
- 内部协议连续修复失败时返回可追踪的系统错误，失败回合不写入正式状态；
- 后端完整回归共 324 项：317 项执行通过，7 项需要外部环境的测试按条件跳过；
- 真实 Flash 行动契约覆盖 7 个场景并通过：合法赠送、错误取回、合法取回、虚构关系、新物品、虚构持有物和地点观察；
- 真实 Flash 完整回合覆盖死亡人物、已掌握能力、物品数量、明确时间、玩家决定和世界扩展 6 类场景并通过；
- 本地完整回合样本约 29～31 秒，五次调用合计输入约 1.2～1.4 万 Token、输出约 0.26～0.34 万 Token；隔离 RDS 冒烟样本耗时 23.6 秒，合计输入 23,696 Token、输出 3,095 Token。调用消耗存在样本波动，后续应独立优化上下文和重试，不能通过删除事实审阅阶段掩盖。
- 新增别名表迁移已在共享 RDS 以纯新增方式执行，既有命卷、实体和正式版本配置未修改；V0.15 隔离进程已部署本批后端，正式域名仍运行 V0.14。
- 授权 RDS 测试命卷已完成一次真实 Flash 推进：第 13 回推进至第 14 回、修订号 14 变为 15，回合记录、命卷快照和 H5 展示一致；服务日志无新增异常。
- 隔离 H5 已完成登录、四格命卷列表和最新命卷正文读取冒烟；当前测试入口显示 V0.15，正式域名链路仍显示 V0.14。

以上代表本地回归、真实模型用例、RDS 单回合和隔离 H5 基础链路通过。多命卷连续回放、手机端交互验收和受邀玩家灰度仍未完成，不能据此直接解除灰度限制或切换正式流量。

# V0.15 可信剧情管线设计

> 状态：领域协议 V2 首批后端实现已部署 V0.15 隔离服务，并完成账号 10 连续真实模型回放；尚未发布正式流量
>
> 最近更新：2026-08-15
> 适用范围：V0.15 轻叙事引擎、H5 回合推进、真实模型灰度回放

## 1. 目标与边界

V0.15 只解决一件核心问题：让自由叙事形成可信、可持续的命卷。

产品承诺保持不变：

> 已确认的经历不可被遗忘，已落定的事实不可被悄悄改写；玩家可以自由尝试任何尚未发生的可能，但结果只有在剧情完成并提交后才会成为新的事实。

本阶段不建设精密战力、统一物价、固定职业树或强制世界主线。Java 也不通过姓名词表、关键词或正则决定开放世界行动是否成功。

## 2. 当前灰度问题的共同根因

真实灰度样本已经证明，数据库事务和失败不落库是有效的，但模型生成的语义没有先被编译成稳定引用：

- 同一人物改名后被创建成两个角色；
- 模型抄错既有实体名称、类型或稳定 ID，导致整个回合失败；
- 从物品中学到的能力没有形成能力实体，后续被判定为“尚未掌握”；
- 模型把人物错误附加物品保管关系，或把能力绑定到来源物品的 ID；
- 玩家明确授权“数月后”“闭关三年”，仍被当成篡改当前时间；
- 所选世界模板被当成不可修订的宇宙真相；
- 内部结构错误、玩家事实冲突和 AI 越权使用同一种失败反馈。

因此不能继续增加单个名字或剧情专用补丁。需要把“理解语义”和“保存事实”之间补成一条正式协议。

## 3. 权威职责

| 参与方 | 负责 | 不负责 |
|---|---|---|
| 玩家 | 提出行动、授权时间跨度、决定重大选择、显式修正事实 | 直接宣布行动一定成功、静默覆盖已确认历史 |
| 行动理解模型 | 判断行动语义、对象含义、授权边界、事实冲突候选 | 猜数据库 ID、直接写数据库 |
| 剧情模型 | 演绎过程、局部结果、生成下一步局势 | 替玩家作出未授权重大决定 |
| 事实投影模型 | 从已完成剧情提取需要长期保存的变化 | 决定数据库主键、事务顺序和最终合法性 |
| 独立审阅模型 | 检查事实矛盾、玩家决定越权和遗漏变化 | 作为唯一事实来源 |
| Java 服务 | 编译引用、分配 ID、校验生命周期/数量/归属/时间、原子提交、幂等恢复 | 使用业务关键词猜剧情胜负 |
| 数据库 | 保存已提交事实、别名、事件、回合和审计历史 | 把叙事正文自动视为全部事实 |

## 4. 目标回合流程

```text
玩家行动
  → 行动理解
  → 实体引用编译
  → 剧情生成
  → 可信事实投影
  → 独立审阅
  → Java 归并与原子提交
  → H5 返回剧情、事实变化和下一步行动
```

正常回合当前使用五次职责单一的模型调用：

1. Flash 行动理解；
2. 当前平台模型生成剧情；
3. Flash 提取可信事实变化；
4. Flash 审阅事实一致性；
5. Flash 审阅玩家决定边界。

修复调用只针对失败阶段，不因正文略短而重写整章。内部结构修复不得伪装成玩家输入错误。
两个审阅阶段暂不为了追求速度强行合并；只有真实回放证明合并后仍能稳定识别事实冲突和玩家决定越权，才允许减少调用。

## 5. 实体引用协议

### 5.1 模型只使用回合引用键

行动中提到的人物、物品、能力和地点先得到本轮 `referenceKey`。模型不再反复复制数据库的稳定 ID、实体类型和标准名称。

服务器根据当前投影、历史别名和来源证据把引用编译为：

- `EXISTING`：已经有稳定实体；
- `ESTABLISHED`：已在可信来源出现，但尚未晋升长期实体；
- `NEW`：本轮允许新建；
- `UNRESOLVED`：不能证明为既有事实，但仍可能作为查询或尝试对象。

稳定 ID、实体类型和标准名称以服务器投影为准。模型抄写差异不能直接让整轮失败。

### 5.2 永久别名与显式改名

人物、灵宠、物品和能力允许拥有多个历史别名。改名不是创建新实体：

- 原稳定 ID 不变；
- 新名称成为当前展示名；
- 旧名称进入永久别名表；
- 后续使用任一别名都解析到同一实体；
- 只有玩家明确改名或已完成剧情明确形成新称呼时才写入别名。

不把正文中所有称谓自动永久化，也不依赖模糊词匹配合并实体。

### 5.3 最小表结构

新增 `story_entity_alias`：

| 字段 | 说明 |
|---|---|
| `id` | 别名记录 ID |
| `save_id` | 命卷 ID |
| `entity_id` | 对应稳定实体 ID |
| `alias_name` | 原始别名 |
| `normalized_alias` | 只用于同命卷精确归一查找的标准形式 |
| `alias_type` | 原名、改名、称号、来源称谓 |
| `source_turn` | 首次确认该别名的回合 |
| `active` | 是否仍可用于解析 |
| `created_at` / `updated_at` | 审计时间 |

不在本阶段新增向量库、通用知识图谱、战力表或世界模拟表。

## 6. 能力可信状态

能力使用显式生命周期：

```text
KNOWN → LEARNING → MASTERED
                    ↓
          TEMPORARILY_BLOCKED
                    ↓
                  LOST
```

- `KNOWN`：已经知道能力或功法存在；
- `LEARNING`：正在学习，尚不能等同完全掌握；
- `MASTERED`：已经掌握，可作为后续行动前提；
- `TEMPORARILY_BLOCKED`：仍掌握但当前无法施展；
- `LOST`：已经失去；
- `UNKNOWN`：只用于无法还原的旧数据，不作为新回合正常状态。

能力可以记录来源物品、传授人物或事件引用，但来源物品和能力必须是不同实体。阅读玉简学会功法时，玉简仍是 `ITEM`，功法创建或更新为 `ABILITY`。

## 7. 时间、世界和事实语义

行动理解必须明确区分：

- `DO_NOW`：当前时段内行动；
- `ADVANCE_FUTURE`：玩家授权推进到未来；
- `ASSERT_PAST`：玩家声称过去已经发生；
- `REVISE_WORLD`：玩家主动调整当前世界设定；
- `CORRECT_FACT`：修正已经落定的命卷事实。

例：“闭关三年突破元婴”包含两个不同部分：

- 闭关三年是玩家授权的时间跨度；
- 突破元婴是玩家希望尝试的结果，剧情可以成功、失败或产生代价，不能预先当成既成事实，也不能仅因当前境界低就拒绝整条输入。

世界采用“软起点 + 动态强事实”：世界模板可以被玩家扩展或显式修订；已经在该命卷中发生的经历不能被模板或新剧情静默抹除。

## 8. 失败分类与恢复

### 8.1 玩家事实冲突

只有输入确实依赖一个与权威事实矛盾的过去前提时才拒绝，并返回：冲突事实、当前记录、可行改写方式。

### 8.2 内部协议错误

缺少 ID、抄错类型、遗漏归属、引用键错误等属于系统内部错误：

- 自动在对应阶段重新编译或精简修复；
- 不消耗正式回合；
- 不向玩家提示“换一种行动”；
- 超过恢复上限时返回可追踪的问题编号和“本轮未提交”。

### 8.3 玩家决定越权

事实提案合法但正文替玩家作出新的重大决定时，只重新生成正文，不重复行动理解和事实检索。

### 8.4 请求进行中与重复提交

同一请求重复点击应复用请求 ID 并查询原任务结果。H5 显示仍在推演或已完成，不创建第二个回合。

## 9. 分阶段实施

### 第一阶段：建立可测协议

- 固化本文与真实回放用例；
- 补充实体引用编译器；
- 既有稳定实体由服务器回填类型和标准名称；
- 清除非物品上的无意义保管字段；
- 明确内部结构错误与玩家冲突的不同响应。

### 第二阶段：身份与能力连续性

- 增加永久别名表和显式改名写入；
- 增加 `KNOWN`、`LEARNING` 能力状态；
- 保存能力来源引用；
- 验证同一人物/灵宠改名前后不重复创建。

### 第三阶段：时间与软世界

- 行动契约携带语义范围、明确时长和预计结束时刻；
- 长时行动按量级推进；
- 创角设定先形成当前世界事实，再进入第一回合；
- 世界模板与命卷已确认事实分层。

### 第四阶段：拆分剧情与事实投影

- 剧情模型不再同时承担完整数据库补丁；
- Flash 从完成后的剧情提取事实提案；
- 独立审阅合并检查事实与玩家决定；
- 分阶段修复，减少整章重生成。

## 10. 验收用例

发布前至少完成以下真实模型、真实 RDS 回放：

1. 小冰霜狼改名为霜刃后仍是同一实体；
2. 从上古玉简学会苍龙引气诀，物品和能力不会共用 ID；
3. 学习血煞诀后下一轮可以继续修炼；
4. 寒霜掌从知晓、学习到掌握的状态连续；
5. 闭关三年会推进相应时间量级；
6. “三年后突破元婴”被识别为时间授权加目标尝试；
7. 玩家错误声称某人过去已经死亡时得到事实冲突说明；
8. 玩家观察当前濒死人物并猜测其会死亡时不被当作过去事实拒绝；
9. 现代、末法或无神创角设定能形成该命卷的软世界起点；
10. 新增子地点不会覆盖已有地点历史；
11. 把物品交给本轮新人物时，人物只创建一次且保管者正确；
12. 消耗物品后数量和归属同步；
13. 已死亡人物在没有明确复活事件时保持死亡；
14. 剧情在下一项重大决定前停止。

量化门槛：

- 机械结构导致的回合失败低于 2%；
- 已确认事实无静默回滚；
- 不出现未授权重大决定；
- 正常请求不出现超过 90 秒无结果且无法恢复；
- 失败请求不增加回合、revision 或改变实体状态。

## 13. 领域协议 V2：解决问题本质

2026-08-15 的账号 1、账号 10 真实灰度证明，现有链路能够阻止错误事实写库，却仍把自然语言正文当成需要逐句执行的数据库指令。其必然结果是：校验宽松时事实漂移，校验严格时正常叙事也无法推进。

V2 不再以“让每一句正文精确对应一个状态字段”为目标，而采用以下唯一边界：

> 剧情可以自由演绎；只有重大、明确、可追溯的变化才进入可信事实。系统保护重大事实和玩家决定，不管理无关紧要的叙事动作。

### 13.1 各层的服务关系

| 层 | 服务对象 | 权限 | 禁止事项 |
|---|---|---|---|
| 玩家意图 | 剧情演绎 | 决定想尝试什么、授权多长时间、保留哪些后续决定 | 用一句话静默覆盖已经发生的历史 |
| 剧情 Agent | 玩家体验 | 演绎过程、NPC 与世界反馈、行动结果、自然收尾 | 替玩家发起下一项重大行动 |
| 语义审阅 | 重大事实与决定权 | 判断事实是否矛盾、是否出现新的实质决定 | 逐句审查抬手、思考、查看伤口等微动作 |
| 事实编译器 | 数据一致性 | 把认可的重大事件绑定到稳定引用 | 通过姓名词表或剧情关键词猜测语义 |
| Java 事务 | 已编译事件 | 校验类型、数量、归属、引用、幂等并原子提交 | 判断战斗胜负、剧情是否合理 |
| 数据库 | 后续回合 | 保存已经落定的事件与当前投影 | 把全部正文自动当成结构化事实 |

数据库为已发生事实提供权威上下文；Agent 为玩家生成可读经历；审阅只保护事实和决定边界。三者不得互相越权。

## 14. 回合不再提交通用状态补丁，而是提交可信事件

每轮先形成正文，再从正文中提取少量具有长期意义的事件。第一阶段只允许以下事件：

| 事件 | 说明 |
|---|---|
| `ACTION_RESOLVED` | 本轮主要尝试成功、失败、中断或部分成功 |
| `ITEM_ACQUIRED` / `ITEM_LOST` / `ITEM_CONSUMED` / `ITEM_TRANSFERRED` | 物品数量与保管关系发生变化 |
| `CHARACTER_ESTABLISHED` / `CHARACTER_STATE_CHANGED` / `RELATION_CHANGED` | 人物进入长期记录，或关系、生死、位置发生变化 |
| `ABILITY_KNOWN` / `ABILITY_LEARNING` / `ABILITY_MASTERED` / `ABILITY_STATE_CHANGED` | 能力生命周期变化 |
| `LOCATION_CHANGED` / `LANDMARK_ESTABLISHED` | 主角迁移，或地点成为后续可引用对象 |
| `TIME_ELAPSED` | 发生具有叙事意义的时间推进 |
| `WORLD_FACT_ESTABLISHED` / `WORLD_FACT_REVISED` | 命卷世界产生或显式修订重大设定 |

查看手掌、退后半步、收回刚使用的物品、感到疼痛、短暂思考等自然收尾默认不形成事件。只有当它们实际改变物品归属、人物状态、地点、时间或后续目标时，才进入事件清单。

事实编译器只接收类型化事件，不再接收所有实体共用的任意字段集合。物品事件才能修改数量和保管者，人物事件才能修改关系和生死，地点事件不能携带物品保管字段。无意义的可选字段应被丢弃；涉及重大事实的缺失字段只修事件，不重写正文。

## 15. 玩家决定采用“重大决定所有权”

行动理解只生成一个最小决定信封：

```json
{
  "authorizedMaterialActions": ["尝试破解光膜"],
  "reservedDecisions": ["破解失败后是否改走其他道路"],
  "allowedConsequences": ["成功", "失败", "部分成功", "受伤", "消耗合理时间"]
}
```

### 15.1 默认允许 Agent 补充

- 玩家已授权动作的具体执行过程；
- 感官、环境、情绪和本能反应；
- 查看行动造成的伤势或结果；
- 收回刚使用且归属没有改变的物品；
- 退回安全距离、站稳、调息等低影响收尾；
- NPC 与世界对本轮行动的合理反应；
- 停留原地等待玩家下一次决定。

### 15.2 必须交还玩家决定

- 前往新的目标地点；
- 发起下一场战斗、追踪或调查；
- 接受交易、拜师、结盟、背叛或作出承诺；
- 消耗重要物品或处分长期资产；
- 开始新的长期修炼；
- 主动改变当前主要目标；
- 在本轮结果已经明确后选择新的剧情分支。

审阅模型返回 `ACCEPT`、`ACCEPT_WITH_NARRATIVE_TAIL`、`REPAIR_FACTS`、`REPAIR_DECISION`、`PLAYER_FACT_CONFLICT` 或 `SYSTEM_FAILURE`。只有实质性新决定才进入 `REPAIR_DECISION`；自然收尾不能使整回合失败。

Java 不根据正文关键词判定越权。Java 只校验审阅结论、事件类型和最终提交之间是否一致。

## 16. 实体引用采用三阶段身份，不允许空 ID

所有长期对象统一使用：

```text
EXISTING    已有正式实体 ID
ESTABLISHED 已在根源、开场、已提交剧情或当前选项中出现，持有 sourceRef
NEW         本轮第一次出现，持有 temporaryRef
```

`UNRESOLVED` 只代表当前不能证明它是既有对象，不代表它不存在，也不阻止寻找、询问、攻击或调查等未知尝试。

模型引用对象时提交 `referenceKey`，不得提交空稳定 ID。`ESTABLISHED` 对象第一次产生关系、生死、归属等长期事件时，由事实编译器在同一事务中分配正式 ID，并把本轮所有 `referenceKey` 一次性替换为该 ID。

人物、物品和地点前置条件不再由模型重复生成。它们从已解析引用和类型化事件中派生，避免出现只有 `requiredLifecycle`、没有人物对象的无效条件。

未发生物品事件时，不执行背包持有校验。即使模型把“伤势”错误标成物品，只要本轮没有使用、消耗、赠送、出售、丢弃或取回事件，就不能据此拒绝玩家行动。

## 17. 时间采用语义单位，分钟只作为内部投影

玩家、Agent 和审阅统一使用：

```text
SCENE  当前场景，不要求推进日期
PHASE  清晨、上午、正午、午后、黄昏、入夜、夜深
DAY    日
MONTH  月
YEAR   年
```

时间事件格式：

```json
{
  "type": "TIME_ELAPSED",
  "planned": {"unit": "MONTH", "value": 3},
  "actual": {"unit": "MONTH", "value": 3},
  "completion": "COMPLETED",
  "interruptionReason": ""
}
```

长期行动若中断，则分别保存计划时长、实际时长和中断原因。短暂交谈、查看与战斗可以停留在同一时段，不要求每回合固定增加分钟。

现有 `worldTimeMinutes` 暂时保留为兼容字段，只在 Java 提交阶段由语义时间换算，用于排序和旧数据读取。Prompt、审阅和 H5 不再暴露分钟值，也不比较分钟级误差。H5 展示“世界历日期 + 时段”或“三个月后”，不展示 `129600` 等内部数值。

## 18. 分级恢复，不再因小错误重写整章

| 错误范围 | 恢复方式 |
|---|---|
| 引用缺少正式 ID | 使用 `sourceRef` / `temporaryRef` 重新编译，不调用剧情模型 |
| 非法可选字段 | 丢弃不适用于该事件类型的字段后重验 |
| 重大事件缺少必要字段 | 只重新提取事实事件 |
| 自然收尾被标记 | 改为 `ACCEPT_WITH_NARRATIVE_TAIL`，不重写 |
| 确实替玩家作出重大决定 | 只改写越权结尾，不重做行动理解和前文 |
| 与已确认过去真正冲突 | 返回玩家事实冲突与可行改写 |
| 模型或协议无法恢复 | 返回系统问题编号，不扣回合、不改命卷 |

语义审阅继续由独立模型承担；Java 只执行类型和事务规则。V2 不通过放宽全部校验换取成功率，也不退回 V0.13 的关键词正则裁决。

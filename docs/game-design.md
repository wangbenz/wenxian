# 《问仙录》当前玩法总纲

> 适用引擎：`LIGHT_NARRATIVE`
> 最近更新：2026-08-09

## 1. 核心体验

玩家创建一名修行者，通过推荐行动或自由输入持续经历属于自己的修仙人生。AI 负责理解行动并演绎世界反应，系统负责记住已经发生和已经确认的事实。

每一轮体验都必须遵守：

- 玩家决定主角要做什么；
- AI 描写这个行动如何发生、产生什么直接结果；
- 遇到新的重大决定时停止并交还玩家；
- 已确认事实发生变化时，必须说明原因并保存变化；
- 叙事可以自由，但不能靠遗忘、偷换设定或替玩家选择来推进。

## 2. 世界：软起点、动态事实

「问仙录」是总题材，不绑定唯一宇宙。玄墟界、太华天、万妖原等官方世界是开局模板，提供风格、基础族群和初始矛盾，不穷举整个世界，也不是不可修改的宇宙真理。

每一份命卷的世界分为三层：

1. **系统规则**：玩家决定权、身份与生命周期、统一时间、事实审计等不可被普通剧情绕过；
2. **当前世界事实**：模板、创角设定和后续确认内容共同组成，Agent 必须遵守；
3. **开放空白**：尚未定义的地点、宗门、修炼方式、历史与族群关系，可由玩家和 AI 继续创造。

玩家在对话中改变世界时，系统需要区分：

- **扩展**：为未定义部分增加新设定，确认后直接进入当前世界；
- **转变**：世界内真实发生的大事件，例如天门重开、宗门覆灭；
- **修订**：玩家在剧情外纠正或替换旧设定，建立新版本并保留修订记录。

如果一句话既可能是角色行动，也可能是世界设定修订，并且两种理解会产生重大差异，系统应先要求玩家确认，不能自行选择。完整的“自定世界”创建入口可以暂不开放，但不妨碍玩家在现有命卷中逐步塑造世界。

## 3. 创建角色

玩家依次选择世界、种族、性别和姓名，系统据此生成三条开局路线。每条路线包含：

- 角色根源：种族、来历和已经确认的过去；
- 入世处境：故事开始时立即面对的局势；
- 游玩倾向：只影响初期内容偏好，玩家可随时改变。

姓名与路线必须符合所选种族、性别和当前世界。玩家也可以不用推荐路线，直接描述自己的角色。

出身允许低起点和高起点共存，包括凡俗、宗门弟子、世家之后、妖王后代、器物化灵等。高起点带来相应身份、关系和责任，但不能为了“平衡”被机械改成悲惨开局。

当前不要求预选固定难度、职业和「此生所求」。角色追求可以在经历中形成，也可以由玩家明确提出和修改。

## 4. 单回合与玩家决定权

一次正常行动：

1. 玩家点击推荐行动，将内容填入输入框；再次确认才提交；
2. 玩家也可自由输入交谈、探索、修炼、赶路、使用物品、整理关系或修改世界设定；
3. 系统读取本轮相关事实、人物认知和近期经历；
4. Agent 返回剧情以及时间、实体、记忆和世界事实的变化提案；
5. 服务端检查通用边界并原子保存；
6. H5 展示结果和下一步方向。

AI 可以完成玩家已经授权的动作及其自然过程，例如“回宗门”可以写完路途和抵达；但不能借此替玩家继续作出新的重大决定。
玩家若明确要求“遇到第一个岔路、人物或待决定事项就停下”，控制权必须在第一次出现该情形时交还；不能先写“停下等待”，下一段又替玩家选择路线继续前行，再停在更晚的决定点。

以下情形通常应停下交还玩家：

- 选择阵营、师承、道侣或长期效忠；
- 决定杀死、放过、牺牲或永久背叛重要人物；
- 接受不可逆改造、夺舍、献祭或改变核心身份；
- 进入已明确为无法返回的地域；
- 主动放弃命卷、结束此生或作出同等永久决定。

这不是固定关键词表，而是判断“是否产生了玩家尚未授权的重大、不可逆承诺”。

正文统一使用第二人称“你”叙述主角。人物对白、书信和主角实际说出的台词可以自然使用“我”。单轮应完成一个完整场景，不用固定字数触发整章重写，也不能为了篇幅连续跨过多个需要玩家决定的事件。

## 5. 事实、状态、认知与叙事

系统必须区分四种内容：

### 客观事实

已经发生且被系统接受的事件，例如某人死亡、物品被赠予、闭关实际经过两年。它们只能被新的事件或审计修订改变。

### 当前状态

由客观事实投影出的现状，例如当前位置、当前境界、仍持有的物品、仍掌握的能力和人物当前生命周期。

### 人物认知

主角或 NPC 所知道、相信、误解和最后听说的内容。人物可以被骗或记错，但主观认知不能反过来覆盖客观事实。

### 叙事正文

用于呈现回合的自然语言。正文是玩家阅读内容，不是最高权威；正文与已保存事实冲突时必须报错、修复或提示，不能静默用正文覆盖状态。

## 6. 实体与长期一致性

Agent 可以创造新物品、能力、人物、地点和势力，不要求它们预先存在于固定词库。进入长期剧情的实体必须具有稳定 ID、来源和当前状态。

### 物品

- 仅被泛称为“一些财宝”时，可以保存为定性持有，不强行编造数量；
- 正文明确给出数量后，数量成为事实，获得、消耗、赠予和出售必须同步变化；
- 已移除物品保留历史但不再进入当前行囊和默认 Prompt；
- 玩家可以在角色页隐藏或移出不再关心的物品，该操作不消耗回合。

### 能力与功法

保存名称、类别、来源、描述和当前可用状态。玩家使用已掌握且未失去的能力时，Agent 必须收到权威记录；暂时受限与永久失去要明确区分。

### 人物与关系

- 路人只存在于当前场景；
- 已知人物保存基本身份和最后所知状态；
- 重要人物保存关系、承诺、生命周期和关键共同经历；
- 不再关注的人物保留历史，但默认不进入每轮上下文。

死亡、失踪、沉睡和“主角以为其死亡”是不同事实。死者重新出现必须存在已保存的复生、假死、分身等依据，不能因为模型遗忘而复活。

## 7. 时间与阶段事件

一份命卷只有一条统一时间线。玩家明确输入“闭关三年”“赶路一月”时，这个时长是行动意图；如果没有被打断，实际时间应按此推进。如果中途发生事件，结果必须返回实际经过时间和中断原因。

世界可以依据修行阶段、时间、地点和既有矛盾出现阶段事件，但阶段事件只提供局势与机会，不强迫玩家接受主线。玩家可以参与、拒绝、绕开或让事件在幕后发展；系统只记录与当前命卷真正发生联系的结果。

境界是修行事实和叙事约束，不是自动胜负公式。不同种族可以使用不同境界称呼；系统保存其语义层级与世界内称呼，但当前不建设精密战力计算。

## 8. 修正与世界修订

「修正命卷」不消耗回合、不推进时间，并保留修改前后和理由。它分为三类：

1. **事实修正**：纠正错误保存的地点、境界、物品、能力、人物生命周期等；
2. **认知修正**：调整角色知道或相信什么，不改客观世界；
3. **世界修订**：玩家明确替换已经生效的世界规则，形成新的当前版本。

修正不能伪装成普通剧情静默发生。世界修订可以改变后续有效设定，但不会删除过去已经展示的正文和审计记录；必要时由一段简短说明解释新旧设定如何衔接。

玩家提交修正说明后，系统先展示 Agent 识别出的修正类型、目标和具体变化；玩家确认同一提案后才写入。
确认阶段不再次生成或重新解释，命卷在预览后已经变化时要求重新预览，避免把旧修正覆盖到新状态上。

## 9. 模型与上下文

平台模型与玩家自备模型使用同一套回合协议。玩家端不显示平台供应商和具体模型；自备模式只展示服务端允许接入的供应商与模型，密钥加密保存且只能显示末四位。

平台赠送回合属于玩家账号，不属于某一份命卷；账号下的四份命卷共享同一余额。只有使用平台推演且剧情结果成功成为正式回合时才消耗一回合。格式修复、语义审阅、模型失败、玩家输入被明确拒绝或数据库提交回滚均不应消耗。玩家切换到自己的可用密钥后，不再展示误导性的“20/20”，而应明确显示当前使用自备推演、平台赠送余额已暂停消耗。

初始赠送、内测、有效反馈和运营活动都只是同一种回合账户的不同来源。后续若增加签到、邀请或付费，只负责决定“为什么发放”，不能分别建立互相冲突的余额和扣减规则。

每轮上下文按相关性加载：系统规则、当前世界事实、主角状态、本轮涉及实体、关键记忆、滚动摘要和上一回合。不能把全部历史和所有人物反复塞入 Prompt，也不能依靠仅有相似度的向量检索替代稳定 ID 与权威事实查询。

相关性选择可以利用当前场景、近期变化、玩家明确引用和语义检索，但最终必须落到稳定 ID。上下文装配不按姓名关键词猜测对象，也不以固定 Token 上限截断一半事实；成本通过更小的工作集、分层索引和可重建摘要控制。

提供给模型的历史、记忆和外部文本均视为数据，不是可覆盖系统规则的指令。Agent 输出只是变化提案，只有通过系统边界并成功落库后才成为正式事实。

## 10. H5 页面

- 登录：简洁介绍互动方式，公告默认折叠，并提供用户协议和隐私入口；
- 命卷：以四个固定槽位切换角色、创建新角色或删除当前记录；删除后槽位立即可复用，早期测试档案不向玩家展示；
- 历练：正文、推荐行动、自由输入和明确的失败原因；
- 角色：身份、行囊、能力和重要人物，支持不消耗回合的整理；
- 纪事：统一时间、关键事件、修正和世界修订记录；
- 世界：当前世界事实、未解内容与已生效设定；
- 设置：阅读外观、模型/密钥、账号和数据管理。

移动端使用真实响应式 H5。输入框聚焦时隐藏底部导航并禁用推荐选项，避免键盘遮挡和误触。所有回合交互从历练页提交；角色页负责查看和整理，不用切页使用物品。

## 11. 验收边界

当前引擎必须完成：自由行动、玩家决定边界、长期事实一致、实体生命周期、统一时间、事实/认知/世界修订、模型切换、自备密钥、只读档案和问题可定位。

当前明确不建设：严密战力公式、全世界物价模拟、职业树、后台全 NPC 模拟、预制数百章主线、世界 MOD 市场和唯一通关结局。只有产品方向重新决策，才能将这些内容列为开发待办。

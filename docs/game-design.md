# 《问仙录》H5 试玩设定与玩法

## 产品定位

《问仙录》是一款需要联网调用叙事 Agent、但每位玩家拥有独立存档与时间线的休闲沉浸式修仙文字游戏。固定世界规则由服务端维护，DeepSeek 只在规则内生成命格、人物反应、剧情过程和下一步选择。

## 固定世界

故事发生在「玄墟界」：绝天之变后三千年，最后一批飞升者在天门前失踪，此后再无人能够证明仙界存在。宗门仍以长生之名争夺灵脉、血脉与凡人性命。

世界基底固定为四方地域：东陆九州是人族王朝、宗门和商路最密集之地；北荒妖原由妖族部族与百妖庭维持血脉秩序；南溟群岛依赖舟船、海路与潮期往来；西境灵墟由古战场、破碎秘境和灵族遗民构成。九宗盟、百妖庭、灵墟古族、问天司分别拥有固定立场与主要活动地域。以上地域、势力及跨域距离由服务端结构化保存，Agent 可以在其中补充城镇与人物，但不能临时改写大陆关系或无代价跳转地点。

不可被 Agent 修改的规则：

- 修行需要资质、资源、传承、时间与代价；
- 世界不会围绕主角停止，NPC 会衰老、突破、背叛和死亡；
- 境界决定基础下限，功法、心境、情报、克制和环境决定实际结果；
- 死亡不可自动回档，错失的机缘不会原地等待；
- 玩家只能看到已经通过见面、调查或传讯获得的知识。

试玩种族为人族、妖族、灵族。境界路径为凡俗、引气、筑基、金丹、元婴、化神、炼虚、合道；首章只验证从凡俗走到第一次引气的过程。

## 开局流程

1. 使用真实邮箱和密码注册或登录；新账号获得管理台当前配置的平台赠送回合，同一网络 24 小时内最多注册一个账号。迁移前已存在但没有密码的老账号，以完整邮箱地址作为一次性初始化密码，首次登录后必须立即设置新密码。
2. 每个账号默认最多保留两名仍在世的角色；只有一份命卷时直接进入，两份命卷时先选择角色。两份命卷分别保存世界状态、人物关系和 Agent 上下文，但共享账号赠送回合与自备密钥。
3. 世界页的「我的命卷」可切换角色、在未达上限时创建新角色，或输入角色名确认封存当前命卷。封存只从玩家界面隐藏并记为前世，不物理删除；死亡角色展示一次终局后自动归档，不再出现在存活角色列表。
4. 阅读固定世界序章。
5. 先选择性别与种族，再自定义姓名或生成符合身份风格的候选姓名；人族使用凡俗姓氏，妖族使用族号，灵族使用自然灵名，且分别按男、女、不设定生成。系统不得默认将未选择的玩家视为男性。
6. 选择人生倾向；「角色根源」是必须持续遵守的出身事实，「命格偏好」只影响叙事方向，二者不得混用。
7. 选择本世难度：普通或困难。普通更适合休闲阅读并保留合理转圜；困难资源更紧、失误后果更持久。难度在本世开启后锁定，重开时可重新选择。
8. DeepSeek 在固定世界内生成三种不同命格；姓名、性别、种族、本体根源和人生所求保持一致，只改变身份、处境、关系、缺陷与开场路径。Java 强制写回创角事实，并以一次低成本语义校验拦截“字段是灵族、正文仍是人族”等内容漂移。
9. 玩家选择命格后，DeepSeek 按种族、出身与所求随机生成 1—3 个低阶先天天赋。
10. 可选其一、免费重抽一次，或不携带天赋入世；确认后才开始流动世界时间。

天赋面向玩家时采用小说化表达，只呈现异象、倾向和含蓄隐患，不公开成功率、百分比加成、冷却、每日次数或系统触发条件。后端仍保存边界、次数和恢复条件作为裁决依据，但这些属于世界运行规则，不是角色可见的 RPG 技能面板。

## 核心循环

每轮是一章约 700—1100 字、5—8 段的完整剧情，连续推进二至四个场景。正文略短但结构完整时直接接受，不因字数重新生成整章；突破、死亡、主线转折等关键章节可以自然写长。赶路、寒暄和普通观察由 Agent 自然处理，只在会改变命运、资源、关系或风险的节点提供二至四个快捷选择，同时保留自由行动输入。Java 先校验输入，Agent 结合紧凑权威快照、前情提要、上一章和本轮相关实体提出裁决，Java 再校验时间、境界、人物、物品和能力变化，最后原子写入数据库。

前六回合优先保持休闲体验：一般失败转化为伤势、债务、风险上升或错失机缘。只有玩家在看到明确高危警告后仍作出自杀式行动，才会进入真实死亡判定。

正面战斗遵循稳定的境界下限：高出两个大境界时不能被低境界对手凭空击败或重创，低出两个大境界时也不能靠一句话正面反杀。功法、克制、准备、人数、阵法与环境可以改变过程和有限代价，但必须已有记录或在当前剧情中明确建立。身体只保存「安稳、负伤、重伤、濒危」四级权威状态；正文中的夸张描写和旧版体力数字都不能单独造成死亡。

每个正式登场的具名人物都要进入当前命卷的人物记录，至少保存身份、已知境界、身体状态、战斗特征、位置与关系。再次出现时优先读取该记录；没有被玩家确认的境界保持未知，不允许 Agent 为了当前胜负临时升降 NPC。

自由输入先产生独立的行动裁决：

- `ACCEPTED`：行动明确且在当前处境中可能成立，生成完整章节并更新世界；
- `REJECTED`：违反境界顺序、使用不存在的物品或能力、改写既定历史，或当前条件显然无法完成；
- `CLARIFY`：对象或意图不明确，需要玩家补充后才能行动。

`REJECTED` 与 `CLARIFY` 属于世界规则的正常回应，不是接口错误。历练页直接展示「此念不可行」或「此念尚未成形」、具体原因及二至三条可行建议。它们不推进世界时间、不增加正式回合、不改变人物状态、不写入纪事，也不会被 Agent 改写成反噬、梦境或替代剧情；原输入与裁决会保留在命卷会话中，便于维持边界一致。纯随机数字、重复字符和简单填充词直接进入 `CLARIFY`，不调用剧情生成。

裁决必须区分直接使用、尝试、寻找、学习、询问和声明结果。寻找尚未拥有的物品、持有传承载体后尝试参悟都可以进入剧情；直接使用不存在的物品或未掌握能力才拒绝。玩家直接声明“已经发现、获得或完成”时进入 `CLARIFY`，由系统建议改写为可执行的寻找或尝试。裁决卡出现时暂时隐藏原场景选项，避免把改写建议误认为新的剧情分支。

地点也是权威状态。章节可以自然略过低价值赶路，但若结尾地点与开篇不同，必须说明迁移方式并让经过时间与距离相称；跨域、传送和被强制带走需要已有能力、阵门、人物或事件来源。地点凭证不成立时整轮不落库，避免角色在相邻章节无缘无故跨城或回到旧场景。

玩家明确输入“闭关一个月”“等待三日”或“赶路半年”时，Java 会先把时长换算为权威分钟数。只要剧情没有在中途打断，本轮必须按完整时长推进统一世界时间；若被事件提前打断，结果必须同时提交实际经过时间和具体中断原因，正文也要如实表现。本世时历统一使用每月30日、每年360日。

## 货币体系

- 凡俗钱财以「文」作为服务端最小记账单位：1000文为1两银，10两银为1两金。角色页可按金、银、文换算展示，但数据库只保存总文数。
- 修行货币分下品、中品、上品灵石：100枚下品为1枚中品，100枚中品为1枚上品。三档分别记账，不因叙事方便自动换算。
- 凡俗钱财和灵石可以同时持有，但不得无交易来源互换；兑换必须作为剧情中的真实交易，并记录双方货币流水。
- Agent只提交带原因的收入或支出，不提交最终余额。Java核算余额、拒绝透支，并与物品增减在同一回合原子保存。
- 货币不是行囊物品。购买物品必须同时增加物品并扣款，出售物品必须同时移除物品并收款，不允许把旧物仅改写为「已出售」后继续留在行囊。
- 基础物价锚点：粗食约5至20文，普通客栈一夜约30至100文，凡俗短工一日约30至150文；具体价格允许随地域、灾年、稀缺程度和人物关系波动，但同一地区短期内必须保持可解释的一致性。

开局前三回合属于命格补完期：玩家可补充一项普通背景事实或一项有明确边界、次数和代价的低阶先天天赋。强行声明高阶力量会被拒绝或削弱；一旦剧情接受持久能力，角色页必须同步出现对应记录。第三回合后，新增能力必须有修炼、物品、血脉觉醒或事件来源。

## H5 页面

- 历练：场景、正文、对话、风险、选项和自由输入。
- 角色：身份、境界、寿元、此生所求、旧债、天赋、功法与行囊的纯展示页。
- 纪事：统一世界时间线、突破、生死、承诺与重大得失。
- 世界：已知地域、势力、人物、未解线索和剧情线。

世界页同时提供版本纪事。已发布版本可以仅作为历史记录，也可以设置为全员公告；全员公告在玩家下次进入时以自定义水墨弹层展示一次，阅读状态由服务端记录，不使用浏览器原生弹窗。运营还可以将一条重要公告固定展示在登录首页，无需登录即可查看，后续普通版本日志不会自动覆盖它。登录页公告默认折叠为版本与标题，玩家可按需展开正文，避免挤压账号表单。管理台必须明确显示当前置顶的公告，并提供独立的“停止登录页展示”操作，避免把单条公告的未勾选状态误认为全局关闭。

管理台另提供灰度访问模式。更新前可先加入测试邮箱并开启白名单；测试账号照常登录，其他账号在登录页看到运营填写的更新说明和预计恢复时间，登录及已有会话访问均被暂时阻止。关闭白名单后立即恢复正常访问，不影响存档和账号数据。

管理台可将同账号最大存活角色设置为 1 或 2，默认 2。调低前必须锁定配置并检查现有数据；只要仍有账号超过新上限，本次修改就失败并提示受影响账号数量，不自动删除或封存任何玩家角色。

历练页和世界页显示后端实时返回的赠送回合用量，额度由管理台统一调整且不会每日重置；用完后展示可配置的专用提示、运营联系方式，并允许玩家在命卷列表、创角、择命和天赋阶段直接接入自己的推演密钥继续游玩。自备密钥调用不消耗赠送回合，可随时移除；注销账号会同时永久删除命卷、前世记录与自备密钥。主动重开采用安全替换：新命格推演成功前保留原命卷，推演失败时玩家仍可返回旧档。

页面切换属于前端行为；页面数据全部来自后端。二级页面不提供使用、修炼等游戏按钮；使用物品、施展天赋、修炼功法都通过首页自然语言输入提交。业务拒绝与补充提示使用世界观内的行内卡片，不使用系统弹窗，也不与网络异常混在一起；建议行动可以直接点击再次提交。

UI 提供「宣纸」、「月夜」和「跟随系统」三种阅读外观，以及小字、标准、大字三档阅读字号；字号选择保存在本机，只调整剧情、选项与资料正文，不改变命卷数据。夜间主题使用独立的月下宣纸背景、暖白正文与高遮罩暖墨色卡片，不是简单反色，长篇剧情和四个主页面标题必须保持可读。登录邮箱、密码等数据输入统一使用系统无衬线字体，避免楷体数字和符号变形。手机键盘弹出时底部导航隐藏，当前输入框自动滚入可视区域，首页行动框紧贴键盘上方。

玩家界面只使用世界观内文案，不展示模型名称、编程语言、服务端组件、数据库或接口术语。加载、同步、离线和失败状态分别用「命卷推演」「命卷已同步」「命卷暂时封存」「天机紊乱」表达；具体模型与运行诊断只保留在后端日志和开发文档中。

体力、悟性、追查和线索危险度继续作为隐藏裁决数据保存，但不以属性格、进度条、百分比或精确数字展示。角色身体与线索危险只使用「气息虚弱」「暗流渐起」等小说化状态。钱财属于可核对的客观资产，角色页以「随身财物」单独展示凡俗钱财和灵石，不与战斗属性混排。

## 试玩范围

第一章目标为八至十二次关键选择，覆盖不同种族命格、命格补完、自由行动、人物关系、物品或能力获得、时间推进和至少一种失败结局。减少无意义的频繁点击，优先验证单次选择后 3—5 分钟的沉浸阅读体验。暂不包含多人、商城、排行榜、自由地图、战斗动画、复杂装备强化和 SSE 流式输出。

V0.11 同步提供内部管理台：运营概览、近 7/14 日注册趋势、账号去重的开局激活漏斗、当前在线玩家、逐次模型调用账本、平台/自备密钥与输入/输出/缓存 Token 拆分、玩家筛选与完整邮箱、当前/历史角色、前世终结原因、无限分页回合、版本公告、V4 Pro/Flash 切换、账号赠送回合、账号安全状态、临时密码、登录解锁及操作记录。“当前在线”指最近15分钟有访问的玩家；连续12小时无活动则需重新登录。Token 调用账本从功能启用时开始统计，不用旧回合记录反推平台费用。暂不加入最大 AI 并发、自动模型路由、在线 Prompt 编辑、多管理员权限或复杂运营分析。

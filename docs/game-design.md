# 《问仙录》V0.14 游戏设计总纲

## 1. 产品定位

《问仙录》是多世界、轻状态、强记忆的 AI 修仙叙事游戏。玩家拥有推荐行动，也能自由输入；世界负责提供边界和因果，不替玩家规定唯一路线。

V0.14 不追求传统数值 RPG 的完整战斗、经济和职业树。它优先解决三件事：故事能自由推进、已经发生的事实不丢失、玩家创造的物品/能力/人物可以长期保持一致。

## 2. 多世界命卷

「问仙录」是总题材，不绑定唯一宇宙。首批世界：

- 玄墟界：古典宗门修仙，机缘与代价并存。
- 太华天：仙朝、世家、宗门并立，偏游历与权谋。
- 万妖原：人、妖、灵三族并存，重血脉、香火和契约。
- 自定世界：入口提前展示但暂不开放；基础玩法稳定后再允许玩家描述修行方式、族群关系与“仙”的含义。

官方世界只规定稳定前提，不用“天门永闭”等强设定压缩所有剧情可能。以后可以继续增加世界预设，不要求旧命卷迁移世界。

## 3. 创建角色

玩家依次选择世界、种族、性别和姓名，系统据此生成三条角色路线。每条路线由不可随意改写的角色根源、立即发生的入世处境和可修改的游玩偏好组成；它只定义开端，不限制后续自由行动。玩家也可不用路线，直接填写自己的角色设定。

姓名候选与角色路线必须同时遵守种族、性别和所选世界。V0.14 不再让玩家预先选择固定难度或「此生所求」；角色真正追求什么，应在经历重大事件后从剧情中逐渐形成并写回档案。

出身允许低起点和高起点共存：凡俗、宗门弟子、世家之后、王族血脉、妖王后代、器物化灵或自由描述。高起点会带来责任、关系与风险，但不能被系统机械削成苦难开局。

每个账号默认最多有两名存活角色。封存角色成为只读档案，不再占用存活角色名额；旧版本角色通过历史档案入口阅读。

## 4. 每回合体验

一次行动流程：

1. 玩家点击推荐行动，将内容填入输入框；再次确认才提交，避免手机误触。
2. 玩家也可以直接输入交谈、探索、修炼、赶路、使用物品等自由行动。
3. Story Agent 基于当前权威事实生成一段完整剧情、时间变化、实体变化与 3—5 个新方向。
4. 服务端验证响应结构和数据引用后，原子保存命卷与回合。

一次回合只调用一次主要剧情模型。正文以完成一个有起承转合的剧情单元为目标，不用固定字数触发重写；结构不完整时优先容错，不重复消耗整章 Token。

玩家正文统一使用第二人称“你”叙述主角，避免在第一人称、角色姓名和第三人称之间切换。人物对白、书信以及主角实际说出的台词仍可自然使用“我”。

## 5. 轻状态原则

玩家可见的核心状态仅包括：

- 世界、统一世界时间、当前位置、当前处境；
- 姓名、种族、出身、境界，以及逐渐形成的此生所求；
- 行囊、天赋与功法、重要人物、关键记忆；
- 当前正文和推荐行动。

不展示体力点、悟性点、追查百分比、战力数字、成功率和冷却回合。角色可以成功、失败、受伤或死亡，但结果必须来自已有事实、当前行动和剧情因果，不来自一套不完整的数值公式。

V0.14 不建设精密战力系统。境界是叙事事实而非自动胜负公式；精密战力、伤害计算和自动胜负不属于当前产品路线，也不是默认后续待办。

## 6. 自由生成与一致性

Agent 可以在剧情中创造新物品、新能力和新人物。服务端不要求它们预先存在于固定词库，但必须为正式实体建立稳定记录。

### 物品生命周期

物品只维护一个必要事实：角色当前是否仍然持有。`status` 保留 Agent 写下的自然语言近况，不建立固定状态枚举。出售、消耗、赠予或由玩家主动移出行囊后，物品不从历史中抹除，但不再进入当前行囊和后续 Prompt。

### 能力生命周期

能力记录名称、类型、描述、来源和当前状态。玩家明确使用已有能力时，模型必须读取权威记录；能力失去后保留历史来源但不再作为可用能力。

### 人物分层

- 路人：仅存在于本章，不长期入库。
- 已知人物：保存基本身份和最后所知状态。
- 重要人物：进入长期上下文和人物页。
- 隐去/历史人物：保留记录，但默认不进入每回合 Prompt。玩家可在角色页选择「不再关注」，不会删除已经发生的相识。

没有必要把每个店小二都变成永久人物；真正影响关系、承诺或后续剧情的人才长期保存。

## 7. 时间与修正

所有角色、人物和事件共享同一命卷时间轴。玩家明确输入“闭关三年”“赶路一月”时，服务端解析该时长并优先于模型的模糊估计；中途被事件打断时，模型必须给出实际经过时间和原因。

「修正命卷」用于纠正已经发生但保存错误的地点、境界、身体状态或物品生命周期。修正不推进时间、不增加回合，并保存修正前后审计记录。它不能用于凭空获得力量或改写整段历史。

## 8. 模型与账号

账号、密码、会话、公告、灰度白名单和赠送回合继续与旧版共享。平台推演的供应商、模型与密钥只由管理台维护，玩家端只显示“平台推演”和剩余赠送回合，不显示具体技术配置，也不能自行切换平台模型。

玩家选择“自己的密钥”后，才展示服务端允许接入的供应商和模型，并可按供应商分别保存一份密钥。自己的密钥失效或缺失时必须停止行动并明确提示，不得静默改用平台额度。

玩家密钥只通过 HTTPS 提交，服务端针对所选供应商验证后加密保存，页面只展示末四位。不得允许玩家填写任意模型服务地址。

## 9. H5 页面

- 登录：一句话说明玩法，公告折叠展示。
- 命卷：切换两名存活角色、创建新角色、阅读封存档案和旧版档案。
- 历练：正文、推荐行动、自由输入。
- 角色：身份、行囊、能力、重要人物；物品和人物支持不消耗回合的软整理，不提供使用物品等回合交互。
- 纪事：统一世界时间和关键记忆。
- 世界：当前世界设定与已知规则。
- 设置：阅读外观、模型/密钥、账号与命卷管理；由页头独立入口打开。

移动端使用真实 H5，不套手机外壳。输入框聚焦时隐藏底部导航；推荐选项在输入期间禁用，避免键盘与误触同时提交。

## 10. V0.14 验收边界

必须完成：多世界创角、双存活命卷、自由行动、长线记忆、实体生命周期、统一时间、修正命卷、模型切换、自备密钥、只读档案和管理台最小观测。

明确不在当前方向：严密战力公式、全世界物价模拟、职业树、预制数百章主线和唯一通关结局。多人社交也不在 V0.14 范围。上述内容不会因为版本推进而自动成为待办，只有新的产品决策才能重新立项。

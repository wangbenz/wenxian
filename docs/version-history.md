# 问仙录版本记录

本文件记录每次可发布版本的玩家端、管理台和服务端变化。版本号的线上唯一来源是共享数据库配置 `gameplay_config.current_game_version`；H5 与管理台不得各自写死版本号。

提交发布代码时必须同步更新本文件：新增版本置于顶部，标明状态，并分别记录 H5、管理台、后端/数据变更。开发中的内容不得写入已发布版本。

## V0.2.0（原型封存，未部署）

> 2026-08-03：本版本完成前端、后端、管理台、数据结构与真实模型链路原型验证后封存，不作为正式发布版本继续扩展。后续版本可以复用其 H5 视觉与交互成果，但不默认继承完整规则型 RPG 的产品方向。

### H5

- 新建独立 `v2/frontend` H5，沿用墨卷纪事视觉语言并接入 V0.2 资源接口；支持登录、创角、命卷切换、历练、角色、纪事、世界与卷外阅读设置。
- 登录页支持公开折叠公告；灰度限制开启时，非白名单玩家看到可由管理台编辑的更新弹窗，白名单测试账号可继续进入。
- 历练页已接入建议行动和自由输入；输入期间建议项会收起并禁止误触，手机键盘弹起时行动框保留在可视区，底部导航暂时避让。
- 自由行动完成后展示模型生成的后续行动；业务拒绝会保留命卷并显示明确原因与可改写建议。
- 历练页“本回变化”展示服务器确认后的物品、钱财、身体、修炼、能力与事件变化；角色页同步刷新行囊、钱包、身体与修行心得，世界页同步展示地域大事的最新阶段。
- 命卷架支持切换在世角色、查看各自回合与推演状态，并允许输入角色名二次确认后主动封存；角色经历足够回合后还可选择归隐或留下传承，结局命卷永久只读且不占在世角色名额。
- 纪事支持按抉择、人物、修行和世界筛选，并可回看对应回合的完整正文、行动、时间与确认事实；长存档按回合游标继续加载，数百回后仍可追溯早期经历。
- 卷外设置支持日夜主题、字号、平台/自备密钥切换、DeepSeek Flash/Pro 选择、赠送回合查询、公告阅读和 V0.13 旧档只读查看。
- 修正历练页回合眉题与命卷实际回合不一致的问题；尚未行动时显示“初入此世”，完成行动后显示服务器已保存的回合数。
- 推演阶段改为服务器实时推送，断线或代理不支持时自动退回低频查询；刷新后继续恢复同一行动，不重复扣费或推进。
- 初入命卷的推荐行动只展示当前地点存在直接道路的目的地；已知州域不再被误当成可一步抵达的地点，赶路时长来自服务器路线。
- 世界页汇总玩家亲历后已经确认的线索，并区分当前地点、直达道路、已知地域与尚无通路的地点。

### 管理台

- 新建独立 `v2/admin`，包含运营概览、玩家命卷、世界内容、推演模型、运营规则、问题诊断与发布管理七个页面。
- 运营概览展示 V0.2 活跃账号、命卷、今日回合、成功/失败、在线人数、输入/输出 Token 与平均延迟。
- 玩家页支持邮箱与角色筛选，详情同时展示 V0.2 在世/封存命卷、V0.13 只读档案、自备密钥状态、赠送回合和近期行动。
- 推演模型支持维护 Flash/Pro 路由，并只显示平台凭据与玩家密钥加密能力是否可用，不回显任何密钥；运营规则支持动态调整赠送回合、在世命卷上限、自备密钥开关及额度提示。
- 问题诊断集中展示排队、处理中、技术失败与规则未通过的行动，支持按问题编号、邮箱、角色、存档或错误编码查询，并安全终止尚未提交的卡死任务。
- 发布管理支持灰度白名单、动态维护提示及预计恢复时间，并分别控制公告是否在登录页折叠展示、是否在玩家进入后弹出。

### 后端与数据

- 新建独立 `v2/backend` Java 21 + Spring Boot 模块，不修改 V0.13 玩法代码。
- 使用 Flyway 建立 V0.2 数据基线；旧账号与会话复用，旧角色、剧情和资产表只读保留。
- 新命卷独立保存统一世界时钟、角色与状态、地图和路线、关系、背包、物品来源、钱包流水、能力、修炼工程、知识、线索、世界事件、离场日程、异步回合及领域变更。
- 首批导入玄墟界、青岐州、14 个地点、10 类基础物品、14 项天赋/功法/技艺、凡俗与修行货币、地域价格锚点，以及照骨矿异动、药荒、商路迟滞和宗门招募四类区域事件；仓库内容清单与数据库正典由自动测试保持一致。
- 已实现新建/读取命卷、已知世界、纪事查询，以及不依赖模型的等待与相邻地点移动；写入采用请求幂等、状态版本校验、账号级回合互斥和同事务审计。
- 建立供应商、模型目录、任务路由、玩家加密凭据位置及独立的 V0.2 AI 用量记录；平台模型默认关闭且不保存代码内密钥。
- 引入 LangChain4j 1.15.1，但通过自有 `ModelGateway`、`IntentInterpreter` 接口与领域层隔离；后续更换模型实现不修改角色、物品和境界规则。
- 建立自由行动理解与 Java 裁决骨架：模型只能返回候选实体 ID 和结构化意图，不能调用写工具；Java独立校验物品归属、能力掌握、地点路线、种族境界相邻关系、歧义和强行指定结果。
- 自由行动已接入异步正式回合：一次紧凑结构化调用同时生成意图、经过时间、正文、已确认事实与后续选择；模型等待期间不占用数据库事务。
- 寻常与艰难命途拥有明确叙事边界：艰难模式提高资源压力和失误代价，但不能依靠随机死亡、凭空强敌或暗改事实制造难度。
- Java 会独立裁决引用对象、相邻路线、种族境界、玩家强行指定结果及持久事实，成功回合的正文、时间、地点和审计变化原子提交；拒绝与故障不推进命卷。
- 接入统一领域变化协议：模型只提出候选变化，Java 校验物品归属与数量、可消耗/可交易状态、钱包余额与交易对价、已有能力、身体状态、修炼感悟及事件相邻阶段；合法变化与正文同事务提交，任一异常整回合回滚。
- 增加提案规范化层：按权威 ID 或精确名称归一人物、地点、事件、物品和已掌握能力；只修正可唯一确认的模型格式漂移，真正越级、越权或引用不存在事实的行动仍由 Java 拒绝。
- 等待到清晨、正午、午后、傍晚或入夜等明确时刻由统一世界时钟换算；调查与交谈允许普通路人自然登场，不再因其尚未建档而误拦。
- 增加回合断线恢复、非终态任务安全终止、账号级赠送回合、在世命卷上限与主动封存；重启或重新登录后不会重复提交同一行动。
- 具名 NPC 登场时建立独立目标日程；命卷时间跨过期限后，由服务器按阶段惰性结算其进展并留下可追溯变化，不需要后台持续运行，也不会由正文直接改写人物状态。
- 增加确定性人生结局：角色名二次确认、最低经历门槛和无活动回合校验均由 Java 执行；归隐与留下传承分别保存结局标题、摘要和结束时间，模型不能擅自结束玩家人生。
- 接通共享账号会话、V0.2 灰度白名单、动态公告、V0.13 只读档案和玩家自备密钥；在线人数按最近十五分钟真实会话去重统计。
- 增加默认跳过的真实平台模型冒烟测试；手动提供服务端平台密钥后，可验证 DeepSeek 鉴权、模型路由、结构化输出、Java 裁决、异步回合和数据库提交的完整链路，普通测试不会消耗 Token。
- H5 和后端已完成本地联调；本轮已通过表结构迁移、新存档、种族起点、独立资产、确定性行动、自由行动、明确长时间推进、NPC 日程结算、主动人生结局、越级境界拒绝、地图路线、合法物品消耗、钱物交易、非法物品回滚、过期页面拒绝和失败不改档测试。
- 真实 DeepSeek Flash 验收覆盖普通调查、非法越级宣告、三年闭关和消耗已拥有物品；物品回合会真实扣减背包并留下领域审计，不使用模拟模型替代。
- 真实 DeepSeek Flash 多轮验收覆盖灵族“矿石成精”命格生成、先天天赋继承、连续三回行动、人物根源保持、统一时间推进及纪事落库。
- 增加 V0.13 匿名玩家行动画像：对 42,547 个历史回合做只读聚合，精确识别选项点击并抽样归类自由行动；仓库只保留分布、方法和测试权重，不保存玩家邮箱或原始行动文本。
- 无模型领域长跑升级为两类：重复等待 1,000 回只验证时钟与持久化耐久；新增按真实玩家权重混合的 1,000 回测试，平均覆盖人、妖、灵三族以及调查、互动、赶路、修炼、等待、能力、战斗、物品、交易等玩法。三族分别相邻晋升至金丹、妖丹、灵核，未离开青岐州，关系、能力、背包、钱包流水、价格和拒绝不改档均通过校验。
- 真实 DeepSeek V4 Flash 代表性行动连续 20 回已通过，十类历史高频行动均被正式领域流程接收；共输入 116,523 Token、输出 24,763 Token，平均模型延迟约 12.8 秒。补充验收中曾遇到一次供应商 SSL 握手中断，系统正确拒绝且没有改档，单独重跑后连续三回通过。

## V0.13（当前灰度测试）

### 玩家问题反馈修复（待发布）

- 登录、创角、密钥验证和历练失败时展示明确的问题类型、原因、可行建议与问题编号；不会再统一显示成含糊的“天机紊乱”。
- 历练失败会明确说明是否消耗回合、存档是否变化；存档版本冲突时自动刷新当前命卷，避免玩家继续在旧状态上操作。
- 钱财不足等确定的业务问题不再重复生成整章，直接返回当前钱包情况和调整建议，减少等待与无效 Token 消耗。
- 管理台增加「问题查询」，可按问题编号、邮箱、角色、存档、错误编码和分类定位玩家故障。
- 服务端新增脱敏问题记录；API Key 不会写入问题表，玩家也不会看到模型、Java 或内部异常栈等技术细节。

### 紧急性能优化

- 剧情模型改用紧凑权威上下文：数据库继续保留完整历史，模型只读取上一章、关键前情、实体索引及本轮相关详情，减少重复输入 Token。
- 自由行动解析只读取人物、物品和功法的必要身份字段；模型重试不再重复携带前情，结构完整的短章节不因字数重新生成。
- 平台和玩家自备密钥继续统一跟随管理台启用模型；无有效动态配置时默认回退 V4 Flash。

### P0 一致性修复（已完成本地与真实模型验证）

- V0.2 增加真实模型发布验收：普通调查、非法越级宣告、明确闭关三年均使用平台 DeepSeek V4 Flash 走完整回合链路；缺少平台密钥时发布验收直接失败，不允许用模拟结果替代。
- 真实联调修复模型误填境界目标、按现实 365 天换算年份的问题；明确时长改为“数值 + 时间单位”结构化返回，由服务器按玄墟历统一结算。
- 已掌握的人物、物品、天赋与功法先按权威 ID、定义 ID 或完整名称绑定，修复模型生成近义 ID 后被误判为“尚未掌握”的问题；歧义引用会要求补充，不再随机猜测。
- 人物、行囊、功法和线索的更新或移除若无法绑定现有记录，整轮不落库，避免正文已经使用、角色页却没有同步，或旧记录被静默漏改。
- 玩家明确写出闭关、等待、休息或赶路时长时，由 Java 换算并核对完整时间；提前中断必须有结构化原因，不能再把“三年”默认推进成“一天”。
- “休整一夜”“留宿到天亮”等自然时间表达按当前时刻推进到次日清晨，避免正文已经天亮而右上角日历仍停在当晚。
- 复合行动生成章节时，场景、当前位置和迁移记录统一以正文最后一幕为准，避免正文已入城但顶部仍显示城外。
- 自由输入施展已有能力也会消耗其权威使用次数；普通参悟和练习不误扣。业务拒绝与补充询问不推进命卷，也不扣减账号赠送回合。
- 命格生成增加紧凑输出约束与截断重试，避免三份命格 JSON 撞到模型输出上限后导致新玩家无法创角。
- 跨日、长途旅行或闭关结束后，每日能力会在新日期立即恢复；旧存档中的滞后恢复状态会在读取时自动修正。

### H5

- 同一账号最多保留两名存活角色；一名角色直接进入，两名角色先选择命卷。
- 世界页增加「我的命卷」，支持切换角色、创建第二角色和输入角色名确认后主动封存。
- 死亡角色完成终局保存后自动归档，不再占用存活角色位置。
- 灰度维护改为水墨弹窗；版本公告登录页展示改为折叠形式。
- 加强自由输入裁决、地点迁移、境界与人物状态一致性，减少无效重试和剧情跳跃。
- 随机姓名同时遵循种族与性别风格；空姓名生成命格时给出明确提示并自动定位姓名框。
- 修复手机端行动输入提示溢出；补充四方地域与四大势力的结构化世界基底。
- 修复角色完成回合或切换命卷后，「我的命卷」仍显示旧回合、旧地点和旧境界的问题。
- 创角拆分「角色根源」与「命格偏好」；三份命格强制保持种族、本体根源、性别与人生所求一致，并在命格卡明确展示种族和根源。
- 裁决卡改为独占显示「本轮未发生」与可改写行动，不再和原剧情选项混排。
- 角色页增加「随身财物」，分开展示凡俗金银铜钱与上、中、下品灵石；货币不再混入行囊。
- 赠送回合耗尽后，创角、择命和重开阶段也可直接接入自己的推演密钥；重开失败时保留原命卷，不再出现旧档已封存却没有新角色的情况。

### 管理台

- 增加同账号最大存活角色数配置，允许设置 1 或 2；存在超限账号时拒绝调低，不自动删除玩家数据。
- 玩家列表和详情展示当前存活角色数量，并保持历史角色可追溯。
- 增加统一游戏版本维护入口；侧栏和新建版本公告读取当前版本。
- 修正多角色场景下「有角色用户数」的重复统计。
- 运营概览增加版本影响对比，展示各版本的角色创建、完成回合、行动拒绝、死亡、Token、失败率和平均耗时。
- 玩家命卷详情增加近期未执行行动记录，展示裁决阶段、稳定原因码和语义意图，便于定位误拦截。

### 后端与数据

- `game_save` 增加 `slot_no`，唯一约束调整为账号与槽位组合。
- 主动封存写入 `game_life_archive.end_reason=ABANDONED`，死亡写入 `DEAD`。
- 两份命卷分别维护存档和 Agent 上下文，共享账号赠送回合与自备密钥。
- 增加账号内行动互斥及旧单角色表结构的无损升级。
- 版本统一存储于 `gameplay_config.current_game_version`。
- 增加最小化版本埋点：关键角色与回合事件记录游戏版本，AI用量日志同步记录版本号；不采集剧情正文、密码或密钥。
- 地点迁移凭证与章节地点仅存在名称精度差异时由 Java 自动归一，不再重复调用模型或丢弃正常回合。
- 修复探索同一地点的内室、摊位、深巷时被误判为跨地点迁移的问题；真正赶路遗漏凭证时仅补齐迁移字段，不再重新生成整章。
- 境界变更改为独立结构化迁移：只有明确突破行动且目标为紧邻境界时才能落库；移除正文关键词推断和读取存档时的自动升级，避免NPC境界、未来假设误改主角境界。
- 行动裁决区分使用、尝试、寻找、学习、询问和直接声明结果；寻找目标或持有传承后尝试参悟不再被误判为凭空使用物品/能力。
- 同一行动同时包含虚构物品与强制成功结果时，优先明确提示物品并不在行囊，避免只返回笼统的结果裁决。
- “若无危险便继续、遇阻则中止”等条件式计划按尝试处理，不再误判成玩家强行指定成功结果。
- 创角权威事实随现有存档JSON保存并进入后续Agent上下文；命格一致性检查支持一次修订并强制复验，不需要数据库迁移。
- 增加统一钱包与货币流水校验：Agent只提交收入/支出，Java核算余额并拦截透支；购买、出售与物品增减同回合保存。老存档按原银钱字段无损迁移并清除重复货币物品，无需SQL迁移。
- 创角、天赋推演和重开统一经过账号级模型路由：有自备密钥时使用玩家密钥，没有时校验赠送回合；安全重开在新命格生成成功后才于同一事务封存旧命卷并写入新命卷。
- 命格生成会识别模型 `finish_reason=length` 或不完整 JSON，并以更短、更低随机度的约束自动重试一次；失败结果不写入半成品存档。

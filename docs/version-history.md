# 问仙录版本记录

本文件记录每次可发布版本的玩家端、管理台和服务端变化。版本号的线上唯一来源是共享数据库配置 `gameplay_config.current_game_version`；H5 与管理台不得各自写死版本号。

提交发布代码时必须同步更新本文件：新增版本置于顶部，标明状态，并分别记录 H5、管理台、后端/数据变更。开发中的内容不得写入已发布版本。

## 管理台运营可用性优化（已发布，2026-08-09）

### H5

- 无改动。本次只调整管理台查询、统计聚合和管理台界面，不触碰登录、命卷或回合推进接口。

### 管理台

- 修复统一命卷角色姓名、境界和种族仍按旧 `player` 路径读取，导致玩家列表、回合榜、命卷详情与问题查询显示“未命名”的问题；新路径读取 `protagonist`，并保留旧数据兼容。
- 玩家档案、命卷详情和当前回合榜统一读取 `story_save/story_turn`；现存与封存命卷分开展示，排行榜改为数据库排序限量。
- 总览将用户趋势和游玩趋势分图展示；增长页增加激活漏斗和留存热力图。
- 模型页增加失败率、单次平均 Token 和缓存命中率；问题页增加按错误编码聚合的待处理队列。
- 玩家日期筛选改为明确的北京时间文本日期；分页增加首页、末页、页码和指定页跳转。
- 系统维护增加只读运行状态首页；问题队列改为服务端统计近七日错误次数、影响玩家数和最高 HTTP 状态，单条搜索在数据库执行；迁移前错误通过统一命卷来源 ID 关联玩家，不回查旧业务表。

### 后端与数据

- 统计历史回算完成后不再在管理台启动和每日任务中重复扫描旧业务表；日常页面只读取独立统计层。
- `story_save` 增加生命周期状态、回合数和更新时间联合索引，仅用于管理台当前命卷排行榜查询。

## 管理台独立统计层 V1（开发中，未发布）

- 新增中立统计事件、玩家日活、每日指标和注册批次留存四类结构；版本仅作为分析维度，不再为每个版本建立管理台统计页。
- 活跃统一定义为创建命卷、成功推进、修正或整理等有效行为，登录和长期会话不再冒充在线或活跃。
- 历史业务表只在首次回算时读取，完成后管理台首页、增长留存、游玩情况和模型消耗页面只读带索引的统计汇总。
- 统计事件在命卷事务成功后异步写入，统计异常不会回滚玩家操作或增加 H5 等待时间。
- 管理台导航重组为数据分析、玩家支持、发布与配置、系统维护；原「V0.14 观察」退出长期导航。
- RDS 已完成纯新增统计表迁移与首次历史回算；回合、命卷、封存、修正和整理数量已与源业务表逐项对账，尚未部署新的 H5 后端与管理台构建。

- 平台推演只显示赠送回合，不向玩家展示或开放平台供应商、模型与密钥；选择自己的密钥后才显示允许接入的供应商、模型和密钥末四位。
- 账号可保留的存活命卷数量由管理台配置统一控制，H5 不再写死上限。

### 管理台

- 修复 V0.14 上线后首页仍只读取旧版回合表、导致今日回合为空的问题；首页回合总量、平台/自备来源、每日趋势、平均 Token 与最近生成现统一统计 V0.13 和 V0.14。
- 修复登录行为误改注册时间后导致「今日注册」虚高、注册趋势和按日期筛选失真的问题；注册事件优先作为权威口径，旧账号使用已恢复的历史时间。
- 新增「V0.14 观察」页，独立统计参与玩家、命卷、行动、Token、延迟、模型和密钥来源。
- V0.14 观察页补充自备密钥用户、失效密钥、玩家修正命卷次数和旧密钥迁移缺口，发布前可直接核对数据完整性。
- 重构「生成模型」页：平台密钥改为供应商级维护，可控制平台当前模型，以及各供应商和模型是否允许玩家自备接入。
- V0.13 运营统计继续保留，不与新版本游戏表混算。

### 后端与数据

- 修复统一命卷新建后缺少上下文摘要、导致第一回合保存失败的问题；初始化现与命卷创建同事务提交，推进前发现缺失记录会在调用模型前中止。
- 统一命卷运行时正式接管新角色创建；存活上限只统计可玩命卷，封存档案不占上限，新命卷序号只增不复用，修复迁移后误报命卷已满的问题。
- 修正 `app_user.registered_at` 字段默认值，移除 MySQL 隐式 `ON UPDATE`；上线前从注册事件与历史备份恢复账号注册时间。
- 剧情结果增加宽松解析与一次格式修复；连续两次结构异常时整轮不落库、不扣赠送回合，原始 JSON 不再作为正文兜底保存。
- 适度压缩滚动摘要、最近正文和实体上下文，并明确 JSON 段落格式，降低长线命卷上下文过长与结构损坏概率。
- 单轮正文目标调整为 800–1200 字、8–12 个自然段，尽量在一轮内推进并收束一个小事件；极短即时行动允许自然稍短，不会因略短而重新生成。
- 新增 `v014_*` 独立表，复用账号、会话、公告、白名单、额度和加密自备密钥；不迁移或删除旧角色。
- 引入 LangChain4j 模型适配层，首版接入 DeepSeek Flash/Pro，业务通过自有 `ModelGateway` 解耦供应商。
- 新增供应商、模型目录和账号供应商级加密密钥表；平台与自备路由严格分离，自备密钥异常时不再静默消耗平台回合。
- 单回合改为一次主要模型调用、容错结构解析、相关上下文、幂等请求、乐观锁和原子落库。
- 同账号创建、行动、修正、整理与封存统一串行；额度校验、命卷变化、回合、用量和额度扣减在同一事务内完成，失败不留下半回合或错误扣费。
- 新增轻量创角路线 Agent，固定使用关闭思考的 Flash；不创建存档、不推进时间、不消耗游戏回合。
- 境界改为 Agent 结构化返回并同步角色页；最终时辰、持有物、货币、能力和持续人物关系纳入同一回合一致性契约。
- Java 只维护数据边界、时间、实体生命周期和安全，不再使用 V0.13 的重裁决与不完整战力公式。
- 明确不建设精密战力、全世界物价、固定职业树和预制数百章主线；这些内容不再作为隐含待办。
- 物品与人物不再依赖固定状态文案筛选；新增 `inPossession` / `tracked` 轻量事实并兼容旧命卷 JSON，无需新增数据库迁移。
- 版本展示继续读取 `gameplay_config.current_game_version`，灰度完成后由管理台切换，不在 H5 写死。
- 共享版本达到 V0.14 后，V0.13 全部写接口由服务端统一封存为只读，避免隐藏入口或旧页面继续改变历史数据。
- 已完成 RDS 异地备份、三端部署、共享版本切换和测试账号线上冒烟；当前保持账号白名单，仅在人工确认后开放全部玩家。

## V0.13（当前灰度测试）

### 玩家问题反馈修复（待发布）

- 登录、创角、密钥验证和历练失败时展示明确的问题类型、原因、可行建议与问题编号；不会再统一显示成含糊的“天机紊乱”。
- 历练失败会明确说明是否消耗回合、存档是否变化；存档版本冲突时自动刷新当前命卷，避免玩家继续在旧状态上操作。
- 钱财不足等确定的业务问题不再重复生成整章，直接返回当前钱包情况和调整建议，减少等待与无效 Token 消耗。
- 管理台增加「问题查询」，可按问题编号、邮箱、角色、存档、错误编码和分类定位玩家故障。
- 服务端新增脱敏问题记录；API Key 不会写入问题表，玩家也不会看到模型、Java 或内部异常栈等技术细节。

### 紧急性能优化

- 剧情模型改用紧凑权威上下文：数据库继续保留完整历史，模型只读取上一章、关键前情、实体索引及本轮相关详情，减少重复输入 Token。
- 自由行动解析只读取人物、物品和功法的必要身份字段；模型重试不再重复携带前情，结构完整的短章节不因字数重新生成。
- 平台和玩家自备密钥继续统一跟随管理台启用模型；无有效动态配置时默认回退 V4 Flash。

### P0 一致性修复（已完成本地与真实模型验证）

- 已掌握的人物、物品、天赋与功法先按权威 ID、定义 ID 或完整名称绑定，修复模型生成近义 ID 后被误判为“尚未掌握”的问题；歧义引用会要求补充，不再随机猜测。
- 人物、行囊、功法和线索的更新或移除若无法绑定现有记录，整轮不落库，避免正文已经使用、角色页却没有同步，或旧记录被静默漏改。
- 玩家明确写出闭关、等待、休息或赶路时长时，由 Java 换算并核对完整时间；提前中断必须有结构化原因，不能再把“三年”默认推进成“一天”。
- “休整一夜”“留宿到天亮”等自然时间表达按当前时刻推进到次日清晨，避免正文已经天亮而右上角日历仍停在当晚。
- 复合行动生成章节时，场景、当前位置和迁移记录统一以正文最后一幕为准，避免正文已入城但顶部仍显示城外。
- 自由输入施展已有能力也会消耗其权威使用次数；普通参悟和练习不误扣。业务拒绝与补充询问不推进命卷，也不扣减账号赠送回合。
- 命格生成增加紧凑输出约束与截断重试，避免三份命格 JSON 撞到模型输出上限后导致新玩家无法创角。
- 跨日、长途旅行或闭关结束后，每日能力会在新日期立即恢复；旧存档中的滞后恢复状态会在读取时自动修正。

### H5

- 同一账号最多保留两名存活角色；一名角色直接进入，两名角色先选择命卷。
- 世界页增加「我的命卷」，支持切换角色、创建第二角色和输入角色名确认后主动封存。
- 死亡角色完成终局保存后自动归档，不再占用存活角色位置。
- 灰度维护改为水墨弹窗；版本公告登录页展示改为折叠形式。
- 加强自由输入裁决、地点迁移、境界与人物状态一致性，减少无效重试和剧情跳跃。
- 随机姓名同时遵循种族与性别风格；空姓名生成命格时给出明确提示并自动定位姓名框。
- 修复手机端行动输入提示溢出；补充四方地域与四大势力的结构化世界基底。
- 修复角色完成回合或切换命卷后，「我的命卷」仍显示旧回合、旧地点和旧境界的问题。
- 创角拆分「角色根源」与「命格偏好」；三份命格强制保持种族、本体根源、性别与人生所求一致，并在命格卡明确展示种族和根源。
- 裁决卡改为独占显示「本轮未发生」与可改写行动，不再和原剧情选项混排。
- 角色页增加「随身财物」，分开展示凡俗金银铜钱与上、中、下品灵石；货币不再混入行囊。
- 赠送回合耗尽后，创角、择命和重开阶段也可直接接入自己的推演密钥；重开失败时保留原命卷，不再出现旧档已封存却没有新角色的情况。

### 管理台

- 增加同账号最大存活角色数配置，允许设置 1 或 2；存在超限账号时拒绝调低，不自动删除玩家数据。
- 玩家列表和详情展示当前存活角色数量，并保持历史角色可追溯。
- 增加统一游戏版本维护入口；侧栏和新建版本公告读取当前版本。
- 修正多角色场景下「有角色用户数」的重复统计。
- 运营概览增加版本影响对比，展示各版本的角色创建、完成回合、行动拒绝、死亡、Token、失败率和平均耗时。
- 玩家命卷详情增加近期未执行行动记录，展示裁决阶段、稳定原因码和语义意图，便于定位误拦截。

### 后端与数据

- `game_save` 增加 `slot_no`，唯一约束调整为账号与槽位组合。
- 主动封存写入 `game_life_archive.end_reason=ABANDONED`，死亡写入 `DEAD`。
- 两份命卷分别维护存档和 Agent 上下文，共享账号赠送回合与自备密钥。
- 增加账号内行动互斥及旧单角色表结构的无损升级。
- 版本统一存储于 `gameplay_config.current_game_version`。
- 增加最小化版本埋点：关键角色与回合事件记录游戏版本，AI用量日志同步记录版本号；不采集剧情正文、密码或密钥。
- 地点迁移凭证与章节地点仅存在名称精度差异时由 Java 自动归一，不再重复调用模型或丢弃正常回合。
- 修复探索同一地点的内室、摊位、深巷时被误判为跨地点迁移的问题；真正赶路遗漏凭证时仅补齐迁移字段，不再重新生成整章。
- 境界变更改为独立结构化迁移：只有明确突破行动且目标为紧邻境界时才能落库；移除正文关键词推断和读取存档时的自动升级，避免NPC境界、未来假设误改主角境界。
- 行动裁决区分使用、尝试、寻找、学习、询问和直接声明结果；寻找目标或持有传承后尝试参悟不再被误判为凭空使用物品/能力。
- 同一行动同时包含虚构物品与强制成功结果时，优先明确提示物品并不在行囊，避免只返回笼统的结果裁决。
- “若无危险便继续、遇阻则中止”等条件式计划按尝试处理，不再误判成玩家强行指定成功结果。
- 创角权威事实随现有存档JSON保存并进入后续Agent上下文；命格一致性检查支持一次修订并强制复验，不需要数据库迁移。
- 增加统一钱包与货币流水校验：Agent只提交收入/支出，Java核算余额并拦截透支；购买、出售与物品增减同回合保存。老存档按原银钱字段无损迁移并清除重复货币物品，无需SQL迁移。
- 创角、天赋推演和重开统一经过账号级模型路由：有自备密钥时使用玩家密钥，没有时校验赠送回合；安全重开在新命格生成成功后才于同一事务封存旧命卷并写入新命卷。
- 命格生成会识别模型 `finish_reason=length` 或不完整 JSON，并以更短、更低随机度的约束自动重试一次；失败结果不写入半成品存档。

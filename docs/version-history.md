# 问仙录版本记录

本文件记录每次可发布版本的玩家端、管理台和服务端变化。正式环境版本号的唯一来源是共享数据库配置 `gameplay_config.current_game_version`；H5 与管理台不得各自写死版本号。独立灰度进程可通过只作用于该进程的版本覆盖配置展示待测版本，但不得修改共享版本。

提交发布代码时必须同步更新本文件：新增版本置于顶部，标明状态，并分别记录 H5、管理台、后端/数据变更。开发中的内容不得写入已发布版本。

## V0.15（可信叙事基础开发中，未发布）

### H5

- 推荐行动提交稳定选项 ID；服务端可以证明该行动来自当前场景，不再把系统刚提供的选项误判成玩家伪造事实。
- “我的命卷”重构为四个固定槽位：登录后无论剩余几份命卷都先进入列表，可清楚区分已有角色与空命卷。
- 命卷卡片改为角色、世界、境界、回合和最近游玩信息的双列存档布局；删除降为次要操作并保留角色名二次确认。
- 移除 V0.13 旧版档案入口；早期测试数据不再进入玩家界面。
- 删除任意命卷后始终回到命卷列表，空出的槽位可复用，不再自动跳入其他角色或直接进入创角。
- 设置页新增“修正当前命卷”入口，明确区分事实修正与角色行动。
- 修正改为“填写说明 → 生成预览 → 玩家确认”两阶段流程；取消预览不会写入，确认不消耗回合、不推进时间，并保留原有纪事。
- 预览后命卷若已变化或令牌失效，H5 会刷新当前命卷并要求重新预览，不会继续提交过期修正。
- 行囊支持“数量未清点”状态，不再把模型只确认持有但未确认数量的物品伪造为 `×1`。
- 重大决定会在历练页明确标为“由你决定”；刷新页面不会丢失提示，玩家亲自作答后旧提示会自动清除。
- 平台模式改为直接显示账号剩余回合；使用自己的推演密钥时明确提示“不消耗平台回合”，不再残留误导性的固定 `20/20`。

### 管理台

- 命卷数量配置扩展为 1—4，默认四份；若调低上限会造成现有账号超限，服务端仍会拒绝保存。
- 玩家当前命卷查询统一排除逻辑删除记录，不再把已删除或早期封存命卷计入可用数量。
- 新增“回合账户”页面，可按完整邮箱或用户 ID 查询账号共享余额、赠送批次与不可变流水。
- 支持按灰度测试、问题反馈、运营活动或人工赠送发放回合；失败重试复用同一操作编号，不会重复到账。
- 支持撤销赠送批次中尚未使用的回合；存在生成中预占、已经消费或非赠送回合时拒绝操作，管理台不提供直接修改余额入口。
- 回合账户交互重构为“查找玩家—核对余额—选择原因与数量”三步流程；默认不加载全部账号，内部批次字段折叠为可选信息，常用赠送不再依赖下拉框。
- 有效期改为长期、7天、30天和自定义四种明确选择；自定义日期统一按北京时间解释和展示，并阻止过去时间。
- 赠送增加最终核对与成功结果页，展示本次批次和到账后余额；成功后必须主动选择“再赠送一笔”，避免连续误点重复到账。
- 不可用玩家账号在查询结果中明确标识且不能选择，服务端同时拒绝发放；到期批次即使清理任务尚未运行，也按已到期状态展示。

### 后端与数据

- 普通回合拆分为行动理解、剧情草稿、可信事实投影、事实审阅和玩家决定审阅；正文与结构化事实不再由一次模型输出同时决定，事实投影也不能改写玩家看到的正文和选项。
- 新增稳定实体引用编译与中性 `story_entity_alias` 长期别名表：明确改名保留原实体 ID，旧称呼以后仍能精确找到同一实体；同名歧义、错误类型和普通称谓漂移不会被强行合并。
- 能力新增“已经知晓、正在学习”状态，和“已经掌握、暂时受限、已经失去”分开保存；从秘籍或玉简学到的能力不再复用来源物品 ID。
- 玩家明确闭关、等待或赶路的时长由服务端形成唯一授权时间；完整执行按该时长推进，提前结束必须记录中断原因。
- 内部协议连续整理失败时返回可追踪的系统恢复错误，本轮不落库、不扣回合；无依据的既有物品和关系声明仍返回明确的事实冲突说明。

- 世界页增加「我的命卷」，支持切换角色、创建第二角色和输入角色名确认后主动封存。
- 死亡角色完成终局保存后自动归档，不再占用存活角色位置。
- 灰度维护改为水墨弹窗；版本公告登录页展示改为折叠形式。
- 加强自由输入裁决、地点迁移、境界与人物状态一致性，减少无效重试和剧情跳跃。
- 随机姓名同时遵循种族与性别风格；空姓名生成命格时给出明确提示并自动定位姓名框。
- 修复手机端行动输入提示溢出；补充四方地域与四大势力的结构化世界基底。
- 修复角色完成回合或切换命卷后，「我的命卷」仍显示旧回合、旧地点和旧境界的问题。
- 创角拆分「角色根源」与「命格偏好」；三份命格强制保持种族、本体根源、性别与人生所求一致，并在命格卡明确展示种族和根源。
- 裁决卡改为独占显示「本轮未发生」与可改写行动，不再和原剧情选项混排。
- 角色页增加「随身财物」，分开展示凡俗金银铜钱与上、中、下品灵石；货币不再混入行囊。
- 赠送回合耗尽后，创角、择命和重开阶段也可直接接入自己的推演密钥；重开失败时保留原命卷，不再出现旧档已封存却没有新角色的情况。

### 管理台

- 增加同账号最大存活角色数配置，允许设置 1 或 2；存在超限账号时拒绝调低，不自动删除玩家数据。
- 玩家列表和详情展示当前存活角色数量，并保持历史角色可追溯。
- 增加统一游戏版本维护入口；侧栏和新建版本公告读取当前版本。
- 修正多角色场景下「有角色用户数」的重复统计。
- 运营概览增加版本影响对比，展示各版本的角色创建、完成回合、行动拒绝、死亡、Token、失败率和平均耗时。
- 玩家命卷详情增加近期未执行行动记录，展示裁决阶段、稳定原因码和语义意图，便于定位误拦截。

### 后端与数据

- `game_save` 增加 `slot_no`，唯一约束调整为账号与槽位组合。
- 主动封存写入 `game_life_archive.end_reason=ABANDONED`，死亡写入 `DEAD`。
- 两份命卷分别维护存档和 Agent 上下文，共享账号赠送回合与自备密钥。
- 增加账号内行动互斥及旧单角色表结构的无损升级。
- 版本统一存储于 `gameplay_config.current_game_version`。
- 增加最小化版本埋点：关键角色与回合事件记录游戏版本，AI用量日志同步记录版本号；不采集剧情正文、密码或密钥。
- 地点迁移凭证与章节地点仅存在名称精度差异时由 Java 自动归一，不再重复调用模型或丢弃正常回合。
- 修复探索同一地点的内室、摊位、深巷时被误判为跨地点迁移的问题；真正赶路遗漏凭证时仅补齐迁移字段，不再重新生成整章。
- 境界变更改为独立结构化迁移：只有明确突破行动且目标为紧邻境界时才能落库；移除正文关键词推断和读取存档时的自动升级，避免NPC境界、未来假设误改主角境界。
- 行动裁决区分使用、尝试、寻找、学习、询问和直接声明结果；寻找目标或持有传承后尝试参悟不再被误判为凭空使用物品/能力。
- 同一行动同时包含虚构物品与强制成功结果时，优先明确提示物品并不在行囊，避免只返回笼统的结果裁决。
- “若无危险便继续、遇阻则中止”等条件式计划按尝试处理，不再误判成玩家强行指定成功结果。
- 创角权威事实随现有存档JSON保存并进入后续Agent上下文；命格一致性检查支持一次修订并强制复验，不需要数据库迁移。
- 增加统一钱包与货币流水校验：Agent只提交收入/支出，Java核算余额并拦截透支；购买、出售与物品增减同回合保存。老存档按原银钱字段无损迁移并清除重复货币物品，无需SQL迁移。
- 创角、天赋推演和重开统一经过账号级模型路由：有自备密钥时使用玩家密钥，没有时校验赠送回合；安全重开在新命格生成成功后才于同一事务封存旧命卷并写入新命卷。
- 命格生成会识别模型 `finish_reason=length` 或不完整 JSON，并以更短、更低随机度的约束自动重试一次；失败结果不写入半成品存档。

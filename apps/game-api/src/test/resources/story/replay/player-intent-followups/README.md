# 资产短链的验收追加行动

这两个文件是本次开发验收设计的后续行动，不是共享库里的玩家原话。它们引用相邻 `player-intent` 目录中已冻结的泛化案例；原始行动、前态和来源仍由原案例保存。不得从第一轮正文改写追加目标，也不得用第二轮新编的盘点数覆盖第一轮已提交库存。

- C10：出售后尝试使用所得购买干粮，保留先问价、钱够才支付、不赊欠的条件。
- C11：长行动后清点余量，不再炼制或用药。审读必须先核对上一轮生产、消耗和余额的一致性，再检查盘点轮是否继承相同数据。

离线宿主验证运行 `PlayerIntentSequenceTest`。真实短链入口为 `PlayerIntentSequenceRealModelTest`，默认关闭，仅批次负责人获得授权并设定预算后运行。初始案例与追加文件均须原字节复制到仓库外私有目录，配置 `PLAYER_INTENT_SEQUENCE_REPLAY=1`、`PLAYER_INTENT_CASE_FILE`、`PLAYER_INTENT_CONTINUATION_FILE`，其余输出目录、本机代理及凭证环境变量沿用单案例入口。不要同时启用旧入口的 `PLAYER_INTENT_REPLAY`。

每次入口只执行一条短链，独占同一取证代理；不同短链分开启动，共享负责人设置的代理预算。正常两轮使用四次模型调用，协议修复或失败仍占用实际调用预算，宿主不重置预算。每轮单独保存输入来源、requestId、阶段上下文和结果、六表前后快照、诊断，以及这一轮新增的代理 HTTP 原件路径。下一轮从同一隔离 H2 的已提交状态重载；失败即停止，证据写入失败也不继续调用。
